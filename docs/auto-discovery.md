# 自动发现服务和容器

“管理 → 服务与容器”会扫描 systemd 用户服务、系统服务和 Docker 容器，包括已安装但未加载的 `.service` 单元以及停止的容器。新安装和已移除的对象会在后续扫描中加入或移出列表；配置中明确保留的对象仍显示其实际状态。

服务页打开且 App 在前台时，约每 10 秒刷新；返回服务页或从后台恢复时重新检查。离开该页、切换管理标签或进入后台会停止这项页面轮询。后端扫描结果最多缓存 5 秒，扫描过程每个读取命令最多等待 4 秒。手动“刷新”也会请求最新可用结果。

可以按容器、用户服务、系统服务筛选，并搜索名称、目标或说明。页面显示实际采样时间；读取失败时保留上次列表并提示失败，部分来源无法读取时明确标注，不把失败当成“没有服务”。

## 发现与控制权限

新发现的非关键运行对象可直接在 App 内点击“授权结束”，查看实际影响并确认后执行，不必先编辑控制清单。这是单次授权，不会自动授予持久的启动、重启或日志权限。系统和桌面基础组件继续只读；`config.json` 中已有授权对象的原有功能仍保留。

- 容器：核验不可变容器 ID 后正常停止，名称相同但已重建的容器需要重新确认。
- 普通用户服务：核验服务、当前启动实例和主进程后正常停止。如果服务设置了停止传播关系，则仅结束主进程，避免连带停止其他单元。
- 其他系统应用服务：不扩大 root 服务执行器的权限，使用已有受限进程管理能力，仅向核验后的应用主进程发送 SIGTERM；服务管理器可能自动重新启动它。缺少管理员进程助手时，App 会说明原因；系统基础进程不会因此获得结束权限。

确认票据绑定配对设备、对象身份和当前启动实例，120 秒有效，只能提交一次。服务重启、容器重建、身份变化、授权到期或票据被其他设备使用时会拒绝执行。请求和工作线程都重核身份及期限；重复请求按原操作编号查询，不会自动补发执行。

如果需要持久的启动、停止、重启和日志功能，可在该服务器自己的 `config.json` 的 `resources` 中加入它，重启后端加载配置。此配置不会随公开源码包或 APK 分发。固定系统服务执行器仍只管理原来的辅助对象；单次结束系统应用主进程复用进程与内存模块的权限检查。

## 来源与限制

- systemd 读取用户/系统的 `list-units` 和 `list-unit-files`；无 systemd 或无法访问会话总线时会标注来源不可读。
- Docker 仅通过本机 Unix socket 执行只读 `ps -a`，不检查或返回容器环境变量、挂载凭据及秘密配置。后端用户没有 socket 读取权限时会显示来源不可读，不会自动修改用户组或 sudoers。
- 当前最多展示 1000 个发现对象，且将回复保持在约 768 KiB 内；超过数量或体积预算时标记结果不完整，保留已配置对象。它不扫描其他主机、远程 Docker context、Podman、Kubernetes 或没有 systemd 单元的任意进程。
- App 会指出旧后端尚未提供自动发现；只更新 APK 无法为旧后端补上主机扫描能力。

维护验证：Python 测试 `tests/test_discovery.py`；启动 `scripts/preview_ui.py` 和 Firefox BiDi 后，可运行 `node scripts/test_discovery_ui.mjs` 验证自动出现、只读操作、搜索、暂停及恢复。界面测试使用模拟数据，不连接真实管理接口。
