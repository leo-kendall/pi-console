# 配置

Android 包名为 `dev.piconsole`。APK 不包含服务器 URL、预配对令牌、RDP 密码、用户应用入口、备份、操作记录或监控历史。首次安装时服务器地址为空、设备未配对、应用入口为空、后台提醒未开启。示例域名只是输入提示，不会自动连接。

## 手机首次配置

1. 安装 APK，打开“设置 → 服务器连接”，填写自己部署的完整 HTTPS API 基础地址并保存。
2. 在服务器终端用运行后端的 Linux 用户，先进入当前 HTTPS 入口对应的后端项目目录（包含 `control.py`），再生成配对码。示例路径须替换为实际安装路径：

   ```sh
   cd /path/to/pi-console
   python3 -B control.py pair
   ```

   将生成的 8 位一次性码填到手机中完成配对。多个后端副本的配对数据相互独立，需在地址对应的那一份目录中操作。
3. 在“应用”自行添加希望打开的网站或网页应用。外观、刷新频率和提醒由每台手机自行设置。

只接受证书受 Android 系统信任的 HTTPS 入口。直接输入 `http://IP:18765` 不能连接；后端默认仅监听回环地址，需要先部署手机可访问的 HTTPS 入口（公网、局域网或 VPN 均可，证书须与域名或 IP 匹配）。`https://pi-console.local/` 只用于在 WebView 内加载 APK 自带界面，由原生代码拦截，不是内置的远程服务器地址。

每次请求同时捕获服务器地址与该地址绑定的令牌。更换服务器前需撤销配对；旧地址的凭据不会作为新服务器的凭据使用。撤销配对也会使尚未完成的配对响应失效。网络不可用时可移除手机本地配对，服务器撤销未确认时应在原服务器执行 `python3 -B control.py revoke-all`。

使用相同签名覆盖安装会保留手机配置。需要重置时，可在 Android 设置中清除 Pi Console 的应用数据，再重新打开。

## 各自服务器的配置

复制 `config.example.json` 为本机 `config.json`，把示例中的服务、容器、目录、挂载点及服务器名称替换成自己的值。示例文件不会自动生效；默认资源白名单为空。支持使用 `PI_CONSOLE_CONFIG` 指定另一份本机 JSON 配置。

| 配置 | 用途 |
| --- | --- |
| `name` | 手机显示的服务器名称 |
| `resources` | 可管理的用户服务和容器的精确名称；系统对象仍仅支持固定辅助服务 |
| `storage_roots` | 存储分析可选目录；默认使用运行用户的主目录、本项目数据目录和用户缓存目录 |
| `disks` | 需要监控的实际挂载点 |
| `desktop_timezone` | 远程桌面时区，默认 `UTC`，使用系统时区库中的名称 |

修改后重启自己安装的后端。远程桌面 Linux 账号、地址和随机凭据由各自服务器的可选安装流程配置；管理员执行器使用安装时指定的 Linux 用户。详见 [部署说明](deployment.md)。

`config.json`、`state/`、`data/` 和 `remote-desktop/connection.json` 都属于本机资料，禁止加入公开源码包。手机配对令牌用 Android Keystore 加密后保存在应用私有目录，禁止 Android 自动备份；源码及 APK 不携带该私有目录。配置导出只包含显式选择的应用入口、外观、刷新频率和服务器告警规则，不导出配对令牌或桌面密码；应用入口 URL 可能包含你自己的私人地址，分享备份前需自行检查。

每台手机有自己的配置和配对身份；同一服务器的服务白名单、监控规则及数据由该服务器所有配对设备共用。当前版本一次连接一台服务器，不提供多账号隔离的托管控制面板。

## 后端版本

建议使用相同版本的 App 和后端。旧后端可能缺少自动发现、动态存储目录或告警接口；App 提示需要更新后端时，应升级对应的服务器副本。
